# 友谊缎带 · 跨组奇偶证明展签工作台

面向数学社班级展览的**纯前端**工具：几名女生把成员、分组（子集 S）、必有/必无/待定的
“友谊缎带”录入后，用一组**结构化证明卡**讲清跨组边数的奇偶结论。每张卡不只检查式子是否
“碰巧成立”，而是：

1. 核对所用规则是否属于允许的六种，并且**形状、前提、引用顺序**都合规；
2. 在**全部满足边约束的图模型**上穷举验证；
3. 第一张错误卡即停，给出**按成员序列边、且 0<1 的字典序最小反例**、卡片两侧取值与依赖链；
4. 若边约束本身无模型，**单独报告“无模型”**，绝不借空模型集的真空蕴含让任何卡通过。

技术栈：React 18 + TypeScript + Vite，关系图为手写 SVG；穷举/剪枝/反例重建运行在
**Web Worker** 中。无后端、无外部服务，草稿只存本地浏览器，可用 JSON 文件在同学之间交接。

## 数学模型与表达式语言

- 成员按 A、B、C…（对应 0、1、2…）序列编号，2–8 人。
- 无向简单图的每条边是一个 0/1 **边指示量**：`xAB` 表示 A、B 之间是否系有缎带。
  边按 `(a,b)`（a<b）字典序编号：n=3 时为 xAB、xAC、xBC。
- `deg(A)` = 与 A 相连各边指示量之和；`within()` = 两端同组（同在 S 或同不在 S）的边数；
  `cross()` = 两端跨组的边数。
- 表达式只允许：边指示量、`deg`、`within()`、`cross()`、整数常量、加法 `+`、减法 `-`，
  以及**一层**二倍项 `2Y`（可写 `2*xAB`、`2(xAB + xAC)`，不允许 `2(2Y)`）。
- 同一条边可重复录入约束，约束之间是**合取**：同边既“必有”又“必无”立即判无模型；
  “待定”不做任何限制。

允许的证明规则（卡片必须声明其一，且引用只能指向更早的卡）：

| 规则 | 形状要求 |
| --- | --- |
| 展开度数 | `deg(V) = 与 V 相连的每条边之和`，不引用前卡 |
| 按边归组 | 0 引用：`within()`/`cross()` 逐条展开为对应边；1 引用：把相同边的裸指示量两两配成 `2*x`（每条边至多剩一条），其它原子与常量原样 |
| 引用已证等式代换 | 把引用等式的**某一侧作为整体**替换成另一侧，可同时引用多张等式卡 |
| 等式两边同加减 | 两边同时加上/减去**同一个非空式** Q |
| 等式传递 | 两前提形如 A=B、B=C（中间端完全一致），本卡 A=C |
| 由 X=2Y+Z 推同奇偶 | 引用等式右边至少含一个二倍项，本奇偶卡为 X≡Z（允许 Z=0、多个二倍项部分留在 Z） |

奇偶式卡片（≡）只能使用最后一条奇偶规则；等式卡（=）不能使用它。

## 校验如何保证“对所有允许连线成立”

所有合法表达式都能线性化为 `d(x) = k + Σ c_e·x_e`（deg/within/cross 本身就是边之和）。
对一张等式卡，检查 `d = 左−右` 是否在每个满足约束的 0/1 赋值上都为 0；对奇偶卡检查
`d` 是否恒为偶数。

- Worker 沿边字典序 DFS，每条自由边**先试 0 再试 1**，因此找到的第一个反例就是字典序最小者；
- 等式剪枝：用自由边后缀系数求可达区间，只在“最终残差只能是 0”时剪枝（恒正/恒负反而是必然失败，不剪）；
- 奇偶剪枝：当前残差为奇即失败可达；为偶时结合固定边贡献与是否还有奇系数自由边判断；
- 规模：8 人 28 条边，无约束时最多 2²⁸ 个模型；约束每固定一条边减半。
  DFS 按预算让出事件循环并响应取消，所以编辑很快时旧任务会作废。

Worker 回传结果带**内容指纹**：主线程只接受与最新编辑指纹相同的结果，迟到结果不会覆盖新状态。

## 本地开发

```bash
npm ci
npm run dev          # 开发服务器
npm run test:run     # Vitest 单元/领域测试
npm run e2e:install  # 首次安装 Playwright Chromium 与系统库（需要本机权限）
npm run e2e          # Playwright 端到端验收（自动构建 + preview）
npm run build        # 类型检查 + 生产构建到 dist/
npm run preview      # 预览生产构建
```

界面操作：左栏录入成员/分组/边约束与目标奇偶式；中栏按序添加等式卡或奇偶卡，
勾选“引用前卡”；右栏查看校验总览、关系图与边字典序明细表。

- 第一张错误卡会**高亮并自动滚动定位**；
- 关系图与边表悬停联动；存在反例时，反例中取值为 1 的边在 SVG 中加粗高亮；
- 草稿自动写入 `localStorage`，刷新可恢复；“导出/交接 JSON”可复制带走、换机器导入。

## Docker

只常驻一个 `web` 服务；宿主端口由 `APP_PORT` 覆盖（默认 4173）：

```bash
docker compose up web --build            # http://localhost:4173
APP_PORT=8080 docker compose up web      # http://localhost:8080
```

`verify` 是**一次性**服务，完成后退出，不常驻：

```bash
docker compose build          # 先准备镜像
docker compose run --rm verify
```

它依次执行：Vitest 单测 → 干净的生产构建 → 对常驻 `web` 的首页探测
（页面需包含“友谊缎带”）→ Playwright 端到端验收，任一步失败即以非零码退出。

## 目录结构

```
src/domain/    表达式解析/线性化、规则形状校验、模型穷举、校验编排（无 DOM 依赖，可单测）
src/worker/    Web Worker（取消、指纹对齐）
src/app/       React hook、指纹、本地草稿与 JSON 交接
src/components/SVG 关系图
tests/         Vitest
e2e/           Playwright
```

## 设计边界（明确不做的事）

- 不支持乘法（除一层 `2Y`）、除法、变量或量词；
- 不做“自动证明”：规则、引用与每一步都由学生自己填写，工具只核对依据与全部模型；
- 没有任何内置的“示例答案”或占位核验，合法链只能通过真实的规则与穷举得到。
